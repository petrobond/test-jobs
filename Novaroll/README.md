# Письмо → карточка CRM

Тестовое задание (кейс A, «Бизнес-аналитик AI»). Инструмент достаёт из входящего письма
структурированные поля для карточки CRM: компания, контакт (имя/e-mail/телефон), суть запроса,
продукт, срочность — и помечает карточки, которые нужно проверить вручную.

## Быстрый старт
```bash
cd Novaroll
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # впишите DEEPSEEK_API_KEY
streamlit run app/streamlit_app.py
```
Docker: `docker compose up --build`. Публикация: Streamlit Cloud (см. `docs/04-deployment.md`).

## Записка (1 страница)

**Какую боль решает и в чём ценность.** Менеджеры вручную переносят данные из писем в CRM —
это медленно и приводит к опечаткам в контактах и перепутанным полям. Инструмент превращает письмо
в готовую карточку за секунду: контактные поля извлекаются идеально (100% на нашем замере),
а каждая карточка несёт уверенность и флаг «проверить» — спорное не уходит в CRM молча. Экономия —
порядка 1.5–2 часов на человека в день при 50 письмах; стоимость — доли цента за письмо.

**Как сделал и почему так.** Извлечение — короткое самодостаточное письмо, поэтому **RAG не нужен**:
вся информация уже в тексте, добавили бы лишнюю сложность. Взял DeepSeek в JSON-режиме, а вокруг —
дешёвую и предсказуемую обвязку: валидация схемой (Pydantic), regex-фолбэк для e-mail/телефона,
`evidence`-цитата под каждое поле и проверка, что значение реально есть в письме. Где хватило промпта —
там промпт; где нужна надёжность — там код. Генерацию синтетики («чистота эксперимента») отдал
**другой** модели, чтобы метрики не были самопроверкой.

**Как понял, что результат достаточно хорош.** Прогнал eval на 16 письмах: точность по полям,
полнота, галлюцинации (значение без подтверждения в письме), работа флага review, латентность и
стоимость — со сверкой с заранее заданными целями (`docs/03-eval-report.md`). Все структурированные
поля (компания, имя, e-mail, телефон, продукт, срок, язык), JSON-контракт и полнота — **100%**;
галлюцинации и ложные тревоги — **0%**; латентность ~3 c, цена ~$0.0003. Слабое место —
субъективное поле `urgency` (**75%**): это разногласие двух LLM по шкале срочности, а не ошибка
извлечения — эталон там сам противоречив (см. отчёт). Галлюцинации ловятся evidence-check’ом
и валидацией схемы.

**Как внедрил бы.** Вывод — готовый JSON, маппится на поля карточки в любой CRM (Bitrix/amo) через API.
Docker — воспроизводимый запуск, Streamlit Cloud — публичное демо. Ключи только в Secrets, ПДн не размножаем.

**Объяснение менеджеру за минуту** — в `script_2min.md`.

**Что улучшил бы за ещё один день.** (1) Интеграция с реальной CRM; (2) калибровка срочности по дате
дедлайна, а не на глаз; (3) третий LLM-судья с рубрикой для объективной оценки; (4) больше краёв в
golden set и разметка человеком; (5) батч-обработка почтового ящика и кэш ответов.

## Структура
```
llm/         транспорт LLM (OpenAI-совместимый), промпты, загрузка ключей
pipeline/    схема карточки, правила-regex, оркестрация извлечения
config/      настройки рантайма и цены
eval/        метрики, пороги-цели, сверка
scripts/     gen_synthetic.py (генерация синтетики), run_eval.py (прогон метрик)
app/         streamlit_app.py (демо)
data/        golden_set/{emails,labels}.jsonl, eval_report.json
tests/       24 теста (сеть мокается)
docs/        01 постановка · 02 промпты · 03 отчёт eval · 04 деплой · 05 демо
```
